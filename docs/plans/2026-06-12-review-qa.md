## A. Orientation

**Q: What is DrugTree, architecturally?**
A dual-stack monorepo: a vanilla-JS atlas frontend and a FastAPI backend, sharing a canonical JSON data layer at the repo root. They talk only over HTTP. The frontend can run standalone against generated embeds (GitHub Pages), so the backend is optional at runtime.

**Q: What is the source of truth at runtime?**
The root `data/*.json` files — served by the backend's in-memory `DataSnapshotService`. SQLite (`drugtree.db`) is used **only** for the `targets` tables and is read-only at request time. ETL owns all writes to `data/`; `scripts/build_frontend_embeds.py` mirrors `data/` into `src/frontend/data/*.js`.

**Q: What was the developer last working on?**
A **two-pane workspace refactor** that has been carried forward into an optimization pass. The current working tree shows: a sticky atlas (left) + scrollable workspace panel (right); a context header (`#workspace-eyebrow/title/subtitle`); custom scroll controls synced via `syncWorkspaceScrollControls()`; orphan-only drug filtering (`orphanDrugIds`, `applySpecialDrugFilters()`); and an anchored in-panel detail page (`#drug-detail-page`, `positionDrugDetailOverlay()`). The old `#modal-overlay` DOM has been removed, though some method names (`showDrugModal()`, `closeModal()`) remain as compatibility wrappers.

## B. Frontend findings

**Q: How healthy is the frontend structure?**
Solid separation overall — stateless utilities (`app-state.js`), pub/sub stores (`selectionStore`, `graphStore`), D3 views, DOM-returning components, an RDKit structure layer, and focused controllers for preview, filters, atlas, and detail. `js/app.js` is still the largest frontend file, but it is down to 1,822 lines and now mainly orchestrates lifecycle/store events plus compatibility wrappers.

**Q: What's the biggest rendering inefficiency?**
At review time, `applyFilters()` coupled the body-map update (B2) into every call, so each **search keystroke** triggered 14 × O(n) per-region drug-count passes even though search never changes the body map. Current update: search is debounced and calls `applyFilters({ updateBodyMap: false })`; region counts are cached; mode switching preserves card DOM; `DrugGridRenderer` performs virtualized/windowed rendering for large visible sets; `DiseaseView.render()` uses a highlight-only path for unchanged signatures. Remaining high-value work is narrower state ownership rather than broad DOM replacement.

**Q: Are there redundant render cascades?**
Partly resolved. `handleRegionSelected()` no longer runs the body-map update twice, and `clearFilters()` now lets `SelectionStore`-backed clears flow through `handleSelectionCleared()` once. Some filter-chip paths still deserve a later diffing/dedup pass.

**Q: How does startup performance hold up given the data size?**
The embed payload is large, but the heaviest full-drug embed and graph bundles are no longer eager. Current measured payloads: `drugs-shell.js` 3.3 MB eager (497.7 KB gzip, 332.3 KB Brotli), `drugs.js` 4.2 MB lazy (722.4 KB gzip, 480.9 KB Brotli), `graph-nodes.js` 1.1 MB lazy (136.0 KB gzip, 108.0 KB Brotli). Remaining payload work is shell trimming and deployment-specific static-host compression config.

**Q: Accessibility?**
Core app a11y is better now: `#drug-detail-page` has dialog semantics, focus trap, and focus restoration; `#drug-grid` has list semantics; result counts are live; cards are keyboard-activatable; disease and genealogy D3 nodes have tree/treeitem roles and keyboard activation. Remaining gap: broader axe/manual screen-reader QA.

**Q: Mobile/touch?**
Functional down to a 390px viewport for the verified core flow. Hover-dwell previews now have touch equivalents for atlas regions and ATC tags; mobile detail placement is fixed within the viewport; the topbar no longer causes horizontal overflow. Full phone-flow UX polish is still future work.

**Q: Any dead code?**
The old `#modal-overlay` DOM is removed. Older modal-centric doc language has been updated in the current docs, and `DetailController` now owns the anchored detail page. Compatibility method names remain in `app.js` so existing call sites and tests keep working.

## C. Backend findings

**Q: How healthy is the backend structure?**
Clean layering: routers → services → models → data. Routers validate with Pydantic and paginate most list endpoints. Services own caching and graph logic. The standout strength is the graph engine (`graph_index.py`): O(1) node/edge/family lookups, BFS neighborhoods, Kahn DAG validation, with `graph_queries.py` adding bucketed, version-hashed caching and hard result caps.

**Q: What's the most important runtime gotcha?**
The graph index is a **process-level singleton**. Current update: startup warms `DataSnapshotService` + `GraphIndex`, `POST /api/v1/admin/refresh` refreshes the snapshot, graph index, and graph query caches, and graph lookup paths auto-refresh when source artifact mtime/size signatures change. Graph query caches include the graph source version.

**Q: Any event-loop hazards?**
Resolved for the current shape. `routers/targets.py` still uses local `sqlite3`, but the blocking work runs behind `run_in_threadpool()`. `GET /targets/{id}` now uses one compound helper/query path for target, drug edges, disease edges, and xrefs while preserving the response shape.

**Q: Pagination coverage?**
The reviewed gaps are now bounded: `/drugs/search`, `/drugs/category/{c}`, `/diseases/search/{q}`, `/diseases/region/{r}`, and `/diseases/{id}/drugs` take `limit`/`offset` with caps. `/tree/disease/{id}` uses explicit `limit`/`offset` instead of a hidden `[:20]` slice.

**Q: ETL state?**
Functional and materially more modular. The five formerly sync-`requests` files (`atc_orchestrator.py`, `drug_etl.py`, `fetch_atc_from_chembl.py`, `fetch_atc_from_kegg.py`, `atc_kegg_api_lookup.py`) have been migrated to `httpx`. The planned B7 split targets are now separated by stage: ATC lookup/enrichment/reporting, drug metadata/transform helpers, disease helpers/source loaders, and validation core/models. `graph_queries.py`, `audit_logger.py`, and `load_graph_edges.py` remain outside this plan's split scope.

**Q: Was the full ETL pipeline run?**
It was attempted with a 60-second timeout and stopped before writes. The launcher requires `data/processed/compound_master_table.tsv`, which is absent in this checkout; the script exited with its own "Input file not found" error before running drug ETL, external fetches, embed regeneration, or SQLite loading.

**Q: Did anything in the old audit turn out to be already fixed?**
Yes. `docs/audits/current-implementation-audit.md` (2026-03-13) said `/health` reported a stale count from `drugs-full.json`; the current `main.py` derives `drugs_count` from `DataSnapshotService`, so that's resolved. Treat that audit as partially superseded.

## E. Cross-cutting risks (top of mind for the next round)

1. **Deployment compression is unknown** — sidecars and local serving are implemented; production static-host behavior needs confirmation.
2. **Accessibility needs a broad pass** — core keyboard/ARIA paths are covered, but axe/manual screen-reader QA is still not checked.
3. **Large non-plan modules remain** — `graph_queries.py`, `audit_logger.py`, and `load_graph_edges.py` are still candidates for future structural work.
4. **Controller interfaces can be narrowed** — the frontend controllers are extracted, but still intentionally use the app object as the first-stage seam.
5. **Docs are now pushable and structured** — keep `docs/modules/`, `docs/plans/`, and top-level architecture maps in sync as follow-up work lands.
